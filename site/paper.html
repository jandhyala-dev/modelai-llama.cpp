The Paper

This fork implements "Fast KV Compaction via Attention Matching" by Zweiger et al. (MIT Han Lab, 2026). Here's what the paper proposes, what we implemented, and where we went further.

The core idea

Traditional methods for managing KV cache size — truncation, eviction, sliding window — all work by removing tokens. The information in those tokens is permanently lost.

Attention Matching takes a different approach: given a full KV cache of N tokens, find a smaller set of M synthetic tokens (M << N) such that the model's attention computation produces the same result. The compacted cache isn't a subset of the original — it's a new, mathematically optimized representation.

The key insight: what matters isn't the individual key-value pairs, but the attention-weighted output they produce. If a smaller set of KV pairs produces the same weighted output, the model behaves identically.

The algorithm

Compaction runs in four stages. Each stage operates independently per attention head per layer.

1 Position selection

Score each of the N original positions by how much total attention it receives across all query tokens. Select the top M positions. These positions form the "skeleton" of the compressed cache. The paper uses attention-weighted scoring; we add Orthogonal Matching Pursuit (OMP) as an alternative for higher quality.

2 Beta fitting (NNLS)

After selection, the attention distribution over M positions won't perfectly match the original over N positions. Beta terms are additive biases injected before softmax that correct this mismatch. Solved via Non-Negative Least Squares (NNLS) with projected gradient descent and regularized Cholesky decomposition (lambda = 1e-6).

3 Value fitting (least-squares)

With positions selected and beta fitted, solve for new value vectors V' such that the attention-weighted sum matches the original: softmax(Q K'^T + beta) V' = softmax(Q K^T) V. Uses a 3-tier cascade: LAPACK QR factorization (most stable), Cholesky decomposition (fast), or aggressive Cholesky (last resort).

4 Execution

During inference, the compacted K', V', and beta tensors are stored as a "compacted prefix" and prepended to the live KV cache. The attention graph injects beta as an additive bias before softmax. Zero-beta layers can use flash attention; non-zero layers use standard attention.

What we extended beyond the paper

The paper provides a Python reference implementation targeting standard attention models. Shipping this in production C++ required significant extensions:

Bugs found during implementation

Translating from Python to C++ and testing across 17 models and 5 architectures exposed bugs that the reference implementation never hit. Three were in the paper's own algorithm:

  • Max-shift inconsistency — Different per-query shifts for target vs design matrix. Fixed with unified shift computation.
  • Beta lower bound too low — Paper uses 1e-12 as floor; should be 0.05 per e^{-3} constraint. Raised the floor.
  • NNLS iterations — Paper's reference uses 64 iterations; convergence happens in 2. Reduced to match.

Plus 15 additional Critical/Major bugs found in the production C++ implementation through adversarial review. Full bug list.

Key design decisions

13 architecture decisions are documented with rationale. Here are the most significant:

1 select is the production default, not solver

The solver pipeline (full beta + V fitting) achieves higher theoretical quality on non-GQA models, but on GQA models (most modern LLMs), it produces cosine as low as -0.174. The select pipeline achieves 0.946-0.999 across all tested models and is flash-attention compatible.

2 All solver math in fp32

Matrix sizes are small (32-256 positions). Mixed-precision artifacts in iterative NNLS are hard to debug. fp32 is fast enough for these dimensions and eliminates a class of numerical bugs.

3 No external dependencies

The solver is pure C++ with optional LAPACK on macOS. Cholesky fallback works everywhere. This matches llama.cpp's philosophy and simplifies the build on embedded / cross-compiled targets.
