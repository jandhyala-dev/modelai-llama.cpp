The problem: LLMs forget

Every LLM stores conversation history in a KV cache (key-value cache). As conversations grow, this cache fills up. When it's full, the model has two options — both bad:

Truncation
Cut off the oldest tokens. The model literally forgets the beginning of the conversation. Ask it about something from 10 minutes ago — it's gone.
Sliding Window
Keep only the most recent N tokens. Same problem: old context is permanently lost. Long documents, multi-turn conversations, and complex reasoning all suffer.

There's a third problem: the bigger the KV cache, the slower inference gets. Attention computation scales with cache size, so long conversations degrade performance even when context fits.

The solution: compress, don't discard

KV cache compaction, based on "Fast KV Compaction via Attention Matching" (Zweiger et al., MIT Han Lab, 2026), takes a different approach. Instead of throwing away old tokens, it compresses them into a smaller learned representation that preserves the model's attention behavior.

1
Fill KV cache fills to capacity (e.g., 64K tokens)
2
Compact Compress at 4x ratio: 64K tokens become 16K compressed tokens
3
Continue 48K slots freed for new tokens. Old context preserved, not lost.
4
Repeat Cycle continues — 256K effective context from 64K physical memory

The compressed representation isn't just a subset of the original tokens. It's a set of synthetic key-value pairs mathematically optimized to reproduce the same attention pattern as the full cache. The model behaves as if it still has the full context.

How compaction works

The algorithm runs in four stages, all in pure C++ with no external dependencies:

1 Select positions

Score each position in the KV cache by how much attention it receives. Keep the most important M positions (out of N total). This is the production-default select pipeline — fast (62-185ms) and flash-attention compatible.

2 Fit correction terms (optional)

For higher-quality compression, solve for additive bias terms (beta) that correct the attention distribution after selection. Uses Non-Negative Least Squares (NNLS) with regularized Cholesky decomposition.

3 Fit compressed values

Solve for new V (value) tensors such that the weighted sum of values matches the original. Uses a 3-tier cascade: LAPACK QR factorization, Cholesky, or aggressive Cholesky fallback.

4 Prepend and continue

The compacted K, V, and beta tensors are prepended to the live KV cache during attention computation. Freed KV slots accept new tokens. The model continues generating with the full context preserved.

Why a fork?

The upstream llama.cpp doesn't have KV compaction. The MIT paper provides a Python reference implementation, but shipping this in production requires a complete C++ rewrite integrated into llama.cpp's KV cache, graph construction, and server infrastructure. This fork does that.

Pure C++
Complete solver engine with zero external dependencies. Optional LAPACK on macOS, Cholesky fallback everywhere else. NEON SIMD + Metal GPU acceleration on Apple Silicon.
Drop-in compatible
Same build system, same CLI flags, same API. Add --endpoint-compact to enable compaction. Without it, the fork behaves identically to upstream.
Weekly upstream sync
Automated Saturday sync from upstream. CI-gated: build + tests + benchmarks must pass. Security patches synced same-day.

18 critical bugs found and fixed

Implementing a research paper in production C++ exposed bugs that the reference Python code never hit. Every bug was found through adversarial review — a 13-section protocol where the reviewer systematically tries to break the code.

Critical
Post-compaction crash Server crashed when reusing compacted slots because the prompt cache held stale position IDs. Fixed by clearing the token record after reclaim.
Critical
NaN propagation When all attention heads were masked, -infinity flowed into value fitting and produced NaN outputs. Fixed with zero-V fallback for masked heads.
Critical
Quality collapse at 8K context The nonuniform pipeline lost >50% of attention heads during union truncation, dropping quality from 0.99 to 0.21. Fixed with automatic fallback.
Major
3.4x decode slowdown Host pointer swap caused 80+ Metal GPU-to-CPU sync stalls per decode batch at 32K context. Fixed with backend-agnostic tensor upload.
Major
16GB memory spike All transformer layers captured query tensors simultaneously during self-study, projecting 16.4GB total. Fixed with a 1GB per-layer capture budget.
Major
Post-compaction amnesia Server forgot the entire conversation after compaction because the token record was cleared. Fixed by preserving history across the compaction cycle.

Getting started

# Build (same as upstream llama.cpp) git clone https://github.com/jandhyala-dev/modelai-llama.cpp cd modelai-llama.cpp cmake -B build -DGGML_METAL=ON cmake --build build --config Release -j$(nproc) # Run with compaction enabled ./build/bin/llama-server \ -m model.gguf \ --endpoint-compact \ -c 8192 # Trigger compaction via REST API curl -X POST http://localhost:8080/compact \ -H "Content-Type: application/json" \ -d '{"id_slot": 0, "method": "select", "ratio": 4.0}' # Or use auto-compaction (triggers when KV fills to threshold) ./build/bin/llama-server \ -m model.gguf \ --endpoint-compact \ --compact-threshold 0.9 \ -c 8192

Public C API

// Trigger compaction programmatically struct llama_compact_params params = llama_compact_default_params(); params.method = LLAMA_COMPACT_SELECT; params.ratio = 4.0f; llama_kv_cache_compact(ctx, params); // Or set auto-compaction threshold llama_kv_cache_set_auto_compact(ctx, 0.9f);
